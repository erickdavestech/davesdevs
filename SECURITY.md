# Política de seguridad

## Versiones compatibles

La única versión compatible es la desplegada desde la rama `main`. Las ramas, forks y compilaciones locales no se consideran versiones de producción.

## Reportar una vulnerabilidad

No publiques detalles sensibles en una incidencia, discusión, pull request o red social.

Utiliza **GitHub Security Advisories** desde la pestaña **Security** del repositorio y selecciona **Report a vulnerability**. Incluye:

- Descripción del problema.
- Ruta o componente afectado.
- Pasos mínimos para reproducirlo.
- Impacto esperado.
- Navegador, sistema o herramienta utilizada.
- Prueba de concepto sin datos de terceros.

## Respuesta

El reporte se confirmará cuando sea revisado. La prioridad dependerá de impacto, posibilidad de explotación y alcance. Los detalles permanecerán privados hasta que exista una corrección o una mitigación segura.

No se autoriza:

- Acceder, modificar o eliminar información de otras personas.
- Interrumpir el servicio o realizar pruebas de denegación de servicio.
- Automatizar tráfico agresivo.
- Intentar acceder a cuentas, infraestructura o servicios fuera del repositorio y la URL pública.
- Publicar una vulnerabilidad sin dar oportunidad razonable de revisión.

Las pruebas deben limitarse a la mínima acción necesaria para demostrar el problema.

## Alcance

Están dentro del alcance:

- Código versionado en este repositorio.
- Dependencias directas declaradas.
- URL pública oficial indicada en el README.

Los servicios enlazados, como GitHub o el portafolio técnico externo, tienen sus propios programas y políticas.
